Track B · Synthea round-trip GT FOUNDATION · ~1-2 days

Render Synthea bundles to PDF, run our pipeline, score against the original bundle. The only fully-trustworthy GT we can generate at scale (no LLM in the loop).
  • B1Pick the renderer: Synthea has a built-in CCDA exporter; pair with weasyprint or Chrome-headless to PDF; alternative: render via clinical-document HTML template + PDF print
  • B2Round-trip one bundle: bundle.json → CCDA → PDF → our extractor → bundle'.json
  • B3Score bundle' vs bundle using the existing score_against_ground_truth() — F1 is meaningful here because GT is absolute
  • B4Sanity: pick 3 patients with different complexity (1 chronic disease, 1 multi-condition, 1 polypharmacy) and round-trip each
  • B5Scale: 100 bundles overnight; aggregate F1 distribution as the headline metric

Track C · Bench upgrades MULTIPLIER · ~2 days

The bench is already there but rough. Make it genuinely comparative — typed Protocol, diagnostic outputs, leaderboard view. Without this, none of the other tracks compose into a presentable story.
  • C1ExtractionPipeline Protocol cleanup — formalize input (PDF or CCDA), output (FHIR Bundle), required metadata (cost, latency, version)
  • C2Diagnostic outputs — per-resource-type F1, failure-mode taxonomy (hallucinations, misses, code mismatches), surfaced in eval.json
  • C3Comparative leaderboard view in app/ (Streamlit page) — runs across pipelines × PDFs as a heat-map
  • C4Reproducibility hashing — pin (pdf_sha, pipeline_version, gt_version) → result_hash so re-runs verify byte-equality
  • C5Document the bench as an extensible interface — "here's how you plug in a new pipeline"

Track D · External parser wrappers EXTENSION · ~2 days

§4Orchestration — how to actually run this

Pattern A — Hybrid: this session orchestrates A+B+C, Codex session runs D Recommended

This session: I dispatch sub-agents per task in Tracks A, B, C using the existing builder pattern (phase1-builder agents from the .claude/ infrastructure already in this repo). I create a queue file at .claude/integration-queue.md (mirroring gold-standard-queue.md), work it sequentially, you check in periodically. Each task is self-contained, ~30-90 min of sub-agent execution time.

Codex session (your machine): open a Codex CLI session, point it at the bench, ask it to wire MinerU and LlamaParse as parallel work. This is independent of the work happening in this session (Track D doesn't conflict with A+B+C if Track C lands first).

Why this is the best pattern:

  • It actually answers §2 of the platform doc — does subscription-economics work for batch eval? Codex on Track D directly tests it.
  • True parallelism without merge risk — Track D touches new files (lib/extract/pipelines/external/*) that nothing else touches. Track A+B+C touches infrastructure that needs coherent ownership.
  • Builds the multi-agent operational story — by the time we submit, we've shown that two independent agent sessions can ship coordinated infrastructure. That's a story for the pitch.
  • Phase 1 deadline pressure — sequential is too slow at 5 days. This is the only pattern that ships everything.

Pattern B — Single session, sequential

I dispatch sub-agents in one session, sequentially. Easiest to reason about, no coordination overhead, you just check in on progress. Downside: ~6-8 days of wall-clock if everything is serial — won't fit before Phase 1 deadline.

Pattern C — Multiple Claude Code sessions

Open 2-3 Claude Code sessions, each owns a track. True parallelism, all in one model family. Downside: subscription rate-limit pressure (we'd be doing a lot of work concurrently), and we'd miss the chance to dogfood Codex specifically.

§6Risks I'd flag

  • Microsoft FHIR-Converter install friction — Node 18+ requirement, npm global install. If the npm path fails, fallback is npx which the existing adapter already supports.
  • Synthea CCDA renderer quality — Synthea outputs CCDA, but the visual rendering layer (CCDA → PDF) may produce too-clean documents. We may need to add visual noise (pseudo-faxes) to make round-trip tests more representative.
  • Codex session rate limits — if Codex hits limits during Track D, we either fall back to API (eats budget) or move D into this session (loses the multi-agent story but ships).
  • Phase 1 scope creep — the temptation will be to wire Track E (Gemma) once we see the others working. Discipline says no — local Gemma is a Phase 2 cost-reduction story, not a Phase 1 capability story.
