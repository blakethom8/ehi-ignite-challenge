Goal: Wire the current `/caspian` workspace to the live provider-assistant runtime so Caspian becomes the real first-party clinical workspace inside the shared Atlas shell, not a fixture-backed chat demo.

Current state:

2. The current `/caspian` route is not wired to it:
   - `app/src/pages/Caspian/Workspace.tsx` mounts `WorkspaceFrame`
   - `WorkspaceFrame` falls back to generic `ChatPane`
   - `app/src/components/atlas/useWorkspaceState.ts` fabricates Caspian replies in `handleSend`
   - `app/src/components/atlas/data.ts` still seeds Caspian fixture chat

   - `app/src/context/ChatContext.tsx`
   - `app/src/api/client.ts` (`chatProviderAssistant`)
   - `app/src/pages/FhirCharts/Assistant.tsx`

4. Citation chips in Caspian open the inspector and load the correct evidence.
5. Caspian uses real assistant state for active sessions instead of static seeded chat.
6. Plugin runtime behavior is not regressed or blurred together with Caspian-specific logic.
7. Tests prove the Caspian workspace is actually wired to the assistant API and that shell interactions still work.
