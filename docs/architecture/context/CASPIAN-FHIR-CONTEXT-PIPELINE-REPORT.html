Caspian context engineering

How Atlas Turns Raw FHIR Into Usable Agent Context

This report documents how Caspian handles FHIR context size. The core design is simple: FHIR remains the source of truth, but the model sees a compact, deterministic, safety-first clinical briefing instead of the raw bundle.

Prepared for clinical AI collaborators Generated from local repo measurements Date: 2026-06-01

Executive Answer

Does Caspian pass the longitudinal patient journey? Yes, but as a compressed journey, not as the full raw longitudinal record. Caspian sends active safety facts, active medications, active conditions, key labs, clinical notes, recent encounters, procedures, historical medication episodes, resolved conditions, explicit absences, and cached care episode briefs when those narrative artifacts exist.

The model is not asked to parse every FHIR resource. Instead, build_clinical_context() prepares a chart briefing that is short enough for normal chat, clinically ordered, and traceable back to the underlying FHIR and SQL-on-FHIR data.

In practical terms, this means Caspian behaves more like a clinician briefing system than a raw FHIR browser. The patient journey is represented by clinical summaries and temporal markers. The raw chart stays available behind the application for citations, drill-down, and deterministic tools.

The Data Transformation Pipeline

Caspian's current context path is a layered transformation. Each layer reduces noise while preserving the evidence needed for clinical reasoning.

Layer 0
Raw FHIR bundle
Patient, MedicationRequest, Condition, Observation, Encounter, Procedure, DiagnosticReport, and related resources.
Layer 1
Shared parser
FHIR is parsed into typed patient models rather than passed to the LLM as JSON.
Layer 2
SQL-on-FHIR warehouse
Selected views and derived tables support deduped meds, latest labs, and queryable chart facts.
Layer 3
Clinical compression
Medication episodes, safety flags, key labs, recent encounters, procedures, absences, and notes.
Layer 4
Prompt rendering
The chart is rendered as compact markdown, ordered by clinical risk and temporal relevance.
Layer 5
Claude call
The model receives the briefing, short recent chat history, and optional workflow instructions.
Pipeline component What it does Primary implementation
FHIR parser Loads the bundle into typed patient structures shared across API and app surfaces. lib/fhir_parser/
Patient loader Resolves patient IDs, demo aliases, and published snapshots; caches parsed records. api/core/loader.py
SQL-on-FHIR Materializes normalized views and derived medication episodes for deterministic retrieval. lib/sql_on_fhir/, data/sof.db
Drug classifier Classifies medications into safety-critical classes and produces surgical risk flags. lib/clinical/drug_classifier.py
Context builder Builds the compact markdown context Caspian sends in the system prompt. api/core/context_builder.py
Caspian chat runtime Sends the context, recent history, workflow packets, and optional file tools to Claude. api/core/provider_assistant_context.py
Virtual system files Expose the exact live system prompt and chart context to the Files pane for transparency. api/core/caspian_context_files.py

What the Longitudinal Journey Looks Like in Context

Caspian does not currently dump a full event-by-event patient journey into every chat turn. It sends a compressed longitudinal briefing with multiple temporal slices:

Journey slice Included by default? How it is represented
Patient voice When cached First-person summary from patient-reported context.
Care episodes When generated EpisodeOfCare briefs loaded from data/narratives/<patient>/.
Active medication story Yes Current meds with status, date, class, duration where available, and indication where resolvable.
Medication history Yes, capped Stopped medications compressed into one-line historical entries.
Active conditions Yes Current problem list with onset or recorded dates.
Resolved conditions Yes, capped Resolved conditions shown after active problems, not interleaved with urgent context.
Recent encounters Yes, capped Recent visits with encounter class, type, reason, provider, and linked-resource counts.
Lab history Latest/key only Key LOINC-driven labs and recent quantitative observations; trend drill-down is a future/on-demand layer.
Raw timeline No Not sent by default because it is too large and low-signal for routine chat context.

Interpretation: Caspian passes enough longitudinal structure for the model to answer "what matters now, what changed recently, and what historical facts still matter." It does not pass the whole FHIR chronology unless a future drill-down tool or workflow asks for deeper detail.

Before and After Example

A raw medication resource repeats FHIR coding, references, dates, status, dosage, requester, encounter links, and other metadata. Caspian compresses that into a clinically useful line.

Raw FHIR shape

{
  "resourceType": "MedicationRequest",
  "status": "active",
  "intent": "order",
  "medicationCodeableConcept": {
    "coding": [
      {
        "system": "http://www.nlm.nih.gov/research/umls/rxnorm",
        "code": "...",
        "display": "Warfarin Sodium 5 MG Oral Tablet"
      }
    ],
    "text": "Warfarin Sodium 5 MG Oral Tablet"
  },
  "subject": { "reference": "urn:uuid:..." },
  "authoredOn": "2001-12-02",
  "reasonReference": [{ "display": "Atrial Fibrillation" }]
}

Caspian prompt shape

## SAFETY FLAGS (Action Required)
- Anticoagulants / Blood Thinners (critical, ACTIVE): Warfarin Sodium 5 MG Oral Tablet
  Action: Bleeding risk - must hold before surgery. Check INR/PT if on warfarin.

## ACTIVE MEDICATIONS
- Warfarin Sodium 5 MG Oral Tablet [anticoagulants] - for Atrial Fibrillation | active | Dec 02, 2001

The prompt shape is not just shorter. It is ordered around the clinical task: risk first, then current therapy, then temporal context and evidence.

What Caspian Sends to the Model

In context mode, the request is assembled in answer_with_context(). The model receives:

Request part Purpose Boundaries
Base system prompt Clinical behavior, safety posture, formatting, and file-tool rules. Static template in provider_assistant_context.py.
Patient chart context Compact clinical briefing from the selected patient chart. Generated by build_clinical_context(patient_id).
Context packages Workflow instructions, such as pre-op review or medication safety review. Up to 8 attached packages.
User overrides Workspace-specific standing instructions. Loaded from user-instructions.md when present.
Chat history Short conversational continuity. Last 6 turns only.
File tools Allow the agent to list, read, and write workspace files when authorized. Demo mode is read-only; authenticated sessions can write notes.

The live context is also exposed to users inside Caspian as the virtual read-only file system-context/patient-chart-context.md. This makes the hidden prompt context inspectable.

Why This Helps With Context Size

Raw FHIR challenge Caspian response Effect
FHIR is verbose and deeply nested. Use typed parsing and selected markdown rendering. Model reads clinical facts, not schema ceremony.
Longitudinal records repeat the same medication many times. Use medication episodes or capped medication summaries. Dozens of MedicationRequests become one clinical line.
Lab and observation volume can dominate the bundle. Use key latest labs by LOINC and cap the default list. Important values are visible; full trend history stays out of default context.
Clinical risk is not ordered in raw JSON. Put safety flags and drug interactions first. The model leads with what can hurt the patient.
Raw context makes citations hard to audit. Keep deterministic retrieval and citation payloads alongside the answer. Users can trace responses back to chart facts.

Current Limits and Next Improvements

Important limit: Caspian's default context is compact by design. If a clinician asks for a full lab trend, a detailed medication chronology, or every encounter in a time window, that should be retrieved by a drill-down tool rather than preloaded into every chat request.

Opportunity Recommended next step
Richer longitudinal journey in Caspian Promote cached EpisodeOfCare narratives into the default context for demo patients that have generated narratives.
Lab trend drill-down Add a dedicated observation drill-down tool by LOINC, date window, abnormality, and source.
Exact token accounting Use Anthropic messages.count_tokens in a valid-key environment to replace rough estimates.
Formal packet contract Convert the markdown context into a typed TUNE-style packet before rendering, with explicit token budgets and evidence-unit counts.
Published demo QA Normalize mixed timezone datetimes in all demo profile bundles before context sorting.

Reproducibility Notes

The measurements in this report were computed from local FHIR bundle sizes and the current Caspian context renderer. The relevant logic is: 

from api.core.context_builder import build_clinical_context

ctx = build_clinical_context(patient_id)
markdown = ctx.to_prompt()
context_tokens = ctx.total_tokens_estimate
fact_count = ctx.fact_count

The raw token estimate used here is len(raw_fhir_json) // 4. The same rough estimator is used by the current context object for display and trace transparency.
