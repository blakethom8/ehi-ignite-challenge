# Jenny M — Document Sources

Five synthetic documents complement the mCODE FHIR Bundle, walking the chart through Jenny M's breast-cancer workup as it would actually arrive: screening imaging, biopsy pathology, multidisciplinary tumor board, genetic counseling, and prior gynecology records from an outside community practice.

All documents were generated by `scripts/synthesize_documents.py` using the FHIR Bundle as ground truth.

## What's in `documents/`

| File | Source | Purpose |
|---|---|---|
| `mammography_report.pdf` | Outpatient Breast Imaging | Initial screening that found the suspicious mass (BI-RADS 4C) |
| `pathology_report.pdf` | Hospital Pathology | Core-needle biopsy result with ER/PR/HER2 biomarker profile |
| `tumor_board_summary.pdf` | Breast Multidisciplinary Tumor Board | Consensus treatment plan |
| `genetic_counseling_letter.pdf` | Cancer Genetics Program | BRCA / multi-gene panel recommendation |
| `outside_records_ccda.xml` | Prior community gynecologist | C-CDA from outside practice — prior benign findings, allergies |
| `patient_app_symptom_tracker_fhir.json` | OncoLife consumer symptom-tracker app | 8 weeks of patient-generated FHIR Observations — nausea, fatigue, pain, daily step counts |

## Deliberate inconsistencies (the demo wedge)

### 1. Family history: maternal aunt vs. maternal grandmother

- The **genetic counseling letter** narrates the family history with the patient's **maternal AUNT** having had breast cancer at age 48.
- The structured **FamilyMemberHistory** resources in the FHIR Bundle attribute that breast cancer to the **maternal GRANDMOTHER**.
- **Why this matters:** the inferred genetic risk and the recommended testing differ subtly depending on which relative was affected, and one of them is going into the structured pedigree that downstream risk models use. Atlas should flag the narrative-vs-structured discrepancy and prompt for clarification before testing is ordered.

### 2. Patient-generated data implies active chemo not in the in-house chart

- The **OncoLife symptom-tracker FHIR feed** contains 8 weeks of daily nausea, fatigue, pain, and step-count Observations consistent with someone actively cycling on chemotherapy (peak nausea days 2-4 post-cycle, fatigue mid-cycle, step count crashes during nausea peaks).
- The **in-house mCODE FHIR record** has Jenny M at the **diagnosis stage** with NO active chemotherapy MedicationRequest yet.
- **Why this matters:** the patient-generated data either (a) comes from a future cycle the in-house chart hasn't caught up to, or (b) means she's getting treatment somewhere we don't have records from. Either way, the harmonization pipeline needs to surface that PGHD implies a treatment phase that the structured chart doesn't reflect.

### 3. Patient identity drift — fuzzy matching test

- The symptom-tracker FHIR feed uses identifier `OL-2024-78492` plus an email-based identifier (`mailto:jennifer.m.1965@gmail.com`).
- The patient's name in the app is `Jennifer M` — not `Jenny M`.
- **Why this matters:** outside data sources reach the platform with their own identifier systems and slightly different name spellings. Harmonization has to do fuzzy patient matching (probabilistic linkage on name + DOB + plausible identifiers) rather than trusting any single identifier. This Bundle is an explicit test case for that path.

## How to regenerate

```bash
uv run python scripts/synthesize_documents.py --persona oncology-breast-mcode
uv run python scripts/synthesize_documents.py --persona oncology-breast-mcode --doc genetic_counseling_letter --force
```

Raw HTML used to render each PDF is cached at `documents/_cache/<name>.html`.
