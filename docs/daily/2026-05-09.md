## Phase 1 perf pass — PDF extraction pipelines

Three coordinated improvements landed on `feature/code-resolution-loinc` (separate branch, kept off master):

### PERF-T01 (commit 6710aa3) — eval/compare honesty

Two-stage fact match in `lib/extract/lab/compare.py`:
- **Stage 1:** exact code match (LOINC, SNOMED, RxNorm, CVX, NPI) — code identity is authoritative
- **Stage 2:** Jaccard fuzzy fallback on aggressively-normalized display tokens, threshold 0.5 — only for code-LESS facts (a code mismatch never gets overridden by display fuzz)

Now matches: "No Known Allergies" ↔ "No known active allergies" / "Progress Note" ↔ "Allergy & Immunology Progress Note" / "Bipartite tibial sesamoid, left" ↔ "Bipartite tibial sesamoid on the left". 599 → +15 new tests.

### PERF-T02 (commit 8bebb9d) — scout no-fallback

Two coordinated changes:
1. Strengthened scout Pass-0 prompts (`_DOCUMENT_MAP_PROMPT`, `_DOCUMENT_MAP_PROMPT_EVENTS`, `_DOCUMENT_MAP_PROMPT_TABLES`) to require all 13 specialist-pass keys in the `presence` map.
2. **REMOVED** the silent fallback in `MultiPassFHIRScoutPipeline._augmented_passes` that ran all 13 passes when presence was empty/all-absent. Per user directive: "we shouldn't allow a fallback pipeline for when one of our pipelines breaks... we need that visibility while we are testing."

Empty/all-absent presence → empty pass list → bundle.entry == [] + WARN log. Visible failure mode by design.

Bidi-scout inherits `_augmented_passes` from parent — fallback removal covers both pipelines automatically.

### PERF-T03 (commit 75fa944) — additive hints

Diagnosed bidi-scout's 44% practitioner F1 (vs default's 93%) by reading `traces/practitioner/prompt.txt` from a real run. Smoking gun: scout had emitted `section_hint = "Steven Krems MD (PCP), Ani Shirvanian NP, plus authorizing providers on labs"` — a content description. The augmented prompt then instructed `Look for the section labeled '<that description>'`, and the LLM literally extracted only the 2 named providers.

Three fixes:
1. Augmentation reframed as **additive hints, not constraints** — "HINT — likely page(s): X. Treat this as a starting point, NOT a constraint. Extract from ANY page."
2. Section_hint guidance tightened across all 3 scout prompts: must be a printed LABEL ("Provider Directory", "Care Team"), never a content description
3. Cosmetic: `\n\n` separator between page-hint and section-hint sentences (was concatenating: `].Look for`)

### Live re-run on cedars-myhealth (PDF SHA 511b7036)

Cache cleared, all 3 pipelines re-extracted against ground-truth v1:

| Pipeline | F1 before | F1 after | Cost | Latency | Entries |
|---|---|---|---|---|---|
| `multipass-fhir` (default) | 98% | 92% | $0.39 | 134s | 198 |
| `multipass-fhir-scout` | 98%* | **0%** | $0.006 | 1.1s | 0 |
| `multipass-fhir-bidi-scout` | 94% | **97%** | $0.40 | 121s | 195 |

**Bidi-scout now beats default by 5 points at comparable cost.** Scout deliberately fails loud (visible failure mode preserved by removing the fallback). Default's 92% isn't a regression — it's the same pipeline measured against the more honest two-stage matcher.

### Key strategic findings

- **TEFCA reframe.** Provider-to-provider record exchange via QHINs is real and working. Atlas's role isn't to compete — it's to (a) ingest records that DON'T flow through TEFCA (paper, faxes, off-network) and (b) synthesize records that DO flow. "TEFCA moves records. Atlas organizes them — wherever they came from."

- **Gold-standard limits.** F1 scores against LLM-generated GT are "agreement with what Opus produced," not absolute pipeline quality. Pipeline rankings remain valid; absolute scores are not.
