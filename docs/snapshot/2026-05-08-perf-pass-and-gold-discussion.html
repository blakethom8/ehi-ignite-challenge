§2The gold-standard run — how does the data feel?

The methodology was: Claude Opus 4.7 with extended thinking, run twice on the same PDF, then intersect — only keep entries that show up in both runs. A reviewer agent (also Opus) then critiques the intersection. Final output: 186 entries, declared GT v1.

The intent was sound. If the most expensive available model, with thinking, agrees with itself across two independent runs, that's a stronger signal than any single run. Self-consistency intersect specifically targets hallucinations — things the model invented in one run but couldn't reproduce in another. Those drop out.

The structural gap

But there's a gap I keep coming back to.

Self-consistency catches hallucinations; it does not catch consistent misses.

If Opus has a systematic blind spot — say, it underweights "Authorizing Provider" stamps on lab-section headers because they're visually ambiguous between "running text" and "structured field" — then both runs miss them, the intersection still misses them, and the reviewer (also Opus) probably agrees with the omission because it shares the bias. The GT then encodes the model's systematic errors as ground truth.

That's not hypothetical. It's exactly what we saw on the bidi-scout investigation: default extracts those Authorizing-Provider stamps cleanly, bidi (with poisoned section_hint) misses them. Whether GT has them depends on which prompt Opus got — and we've now seen evidence that the prompt shape changes which entities Opus surfaces.

Reviewer-as-LLM-judge collapse

The reviewer step has a known failure mode too. When the reviewer shares model family with the extractor, it tends to agree more than a human would. The reviewer flags "this looks wrong" mostly when the wrongness is in the model's own surface failure modes, not the deeper systematic ones. So the review pass doesn't add as much independent signal as it appears to.

What the data actually feels like

Honestly: better than nothing, much better than hand-extracting 186 facts, and useful for comparing pipelines to each other — relative ranking is reliable. But it's a scaffold, not bedrock. We can't claim "97% F1" as an absolute statement of pipeline quality — we can claim "97% agreement with what Opus-with-thinking produces, intersected with itself."

Implication

A measurement system where the GT is generated by the same model class we're testing is biased toward agreement with that model. Pipeline rankings are valid; absolute scores are not.

Two ways to harden the GT

  1. Cross-model gold. Add a third extractor in a different model family — Gemini 2.5 Pro or GPT-5 with vision — and require 3-of-3 agreement (not 2-of-3). Mismatches across families are more meaningful than mismatches within. Costs another ~$3 per gold pass.
  2. Synthea round-trip for golden test set. We already have 1,180 Synthea bundles. If we render one to a clinical-PDF format and run our pipeline on it, the original bundle is the GT — by construction, no LLM in the loop. That gives us a held-out anchor where we genuinely know the answer. Downside: rendered Synthea PDFs are cleaner than real-world EHI exports, so high F1 there doesn't translate directly.

The combination — Synthea round-trip as the absolute anchor, cross-model gold as the relative anchor on real PDFs — is probably what we want before we trust any number we publish.

§3MinerU & LlamaParse — what they actually do

Both are document parsers, not extractors. They take a PDF and return structure — markdown, JSON-typed blocks, bounding boxes — but they don't know what FHIR is. So "wrapping" them is a two-stage operation.

Stage 1 — document → markdown

MinerU (opendatalab, Apache-2.0) runs locally. It chains layout detection (DocLayout-YOLO) → table recognition (SLANet+) → formula recognition (UniMERNet) → text in reading order (PaddleOCR or VLM-pipeline). v1.5 added a VLM backend. Output is markdown with bbox per element. Currently scores 86.2 on OmniDocBench v1.5 — open-source SOTA.

LlamaParse (LlamaIndex) is the SaaS equivalent — REST API, 1,000 pages/day free tier. Best-in-class table extraction across multiple 2026 comparison benchmarks. Has a "premium" mode that uses VLMs for harder layouts.

Reducto is the same shape but HIPAA/SOC 2-compliant — relevant for production, not for benchmarking.

Stage 2 — markdown → FHIR

This is where our existing per-resource Pydantic schemas come back in. We feed the markdown plus the schema to a cheap text model (Sonnet 4 or even Haiku) via call_with_schema() — which already exists in lib/extract/pdf.py. No vision call needed because the parser already did the visual work. So the "expensive" model only sees text, which is 5–20× cheaper than image input.

The quality question

Cost-shape is clear; quality is genuinely unknown. Two competing hypotheses:

  • Vision is essential. The image carries information markdown can't — faint stamps, hand-annotations, table-vs-image ambiguity, layout that disambiguates "MD" suffix from "MD" prefix. MinerU's markdown drops this and we lose recall.
  • Vision is overkill for clinical PDFs. Clinical exports are tabular, machine-rendered, mostly black-on-white. MinerU's structured markdown captures everything that matters; we've been paying for vision we don't need.

The bake-off settles it. And the failure modes are diagnostic: if MinerU-wrapper drops practitioners but keeps labs, we know where vision matters and where it doesn't, and we can pick the right tool per pass — vision for narrative, parsed-text for tables.

Comparative-baseline value

Independent of cost, there's a second reason to wire these up: if our Claude pipeline doesn't beat MinerU on structure recall, the wedge isn't really "we extract better than open source" — it's narrower than that. Possibly "we extract clinical semantics better." That's still defensible but it tightens the story.

§4Where I'd actually focus

Given how much of this conversation is about ground truth, I think the highest-leverage move is Synthea round-trip first, then MinerU wrapper.

The Synthea round-trip gives us the first GT we can fully trust. ~4 hours of work — render a Synthea bundle to PDF (Synthea has a built-in CCDA/CDA renderer, or we use a simple HTML→PDF pipeline), run our pipeline, score against the original bundle. If we hit 80%+ F1 on a known-answer test, that's a number we can stand behind in a way the 97% currently isn't. It also lets us run hundreds of test PDFs cheaply (Synthea bundles are free), which is the test bench we don't have today.

Then MinerU-wrapper makes sense as the next experiment because we'd finally have a metric to evaluate it against. Without trustworthy GT, comparing pipelines is comparing-shadows.

LlamaParse would come third — same wrapping pattern, just SaaS, useful for the "what does buying look like" data point but not a foundation.
